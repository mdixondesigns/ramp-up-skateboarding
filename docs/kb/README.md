# Knowledge base

What we know about Ramp Up as a business, kept next to the code so any person
or agent working on the site has the same facts.

**Load only the file the task needs.** That is the whole point of splitting it
up. `AGENTS.md` in the repo root has the routing table.

| File | Covers |
| :--- | :--- |
| `brand-voice.md` | How everything should sound. Read before writing any copy. |
| `business.md` | Legal shape, who's who, service area, revenue model, partners, values. |
| `history.md` | Origin story and growth numbers, for the About pages. |
| `programs.md` | The level ladder, how kids progress, site structure for Programs. |
| `curriculum.md` | What happens in a class, day by day. |
| `operations.md` | Group sizes, coaching, venues, weather, gear, registration. |
| `pricing.md` | What is published, what is internal, how prices are shown. |
| `terminology.md` | Skate terms with plain-English glosses for parents. |
| `content-rules.md` | What must not be published, and decisions already made. |
| `open-questions.md` | Known unknowns. Ask rather than guess. |

## Provenance

Plain statements came from Mike or Christine directly. Anything marked
`[proposed]` is an unconfirmed suggestion from a previous session. Never
present a `[proposed]` line as fact, and do not remove the marker without
confirmation.

## Keeping it current

Update the relevant file in the same pass as the change. A knowledge base that
lags reality is worse than none, because it gets trusted.
